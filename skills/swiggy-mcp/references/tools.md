Free flow: create_event_cart(checkoutMode=FREE) → user confirms → place_event_order(FREE), which recreates/reprices the selected cart and atomically checks out only if billToPay=0 and skipPayment=true.

INPUTS:
- cartKey: from create_event_cart
- paymentMethod: "UPI" for paid tickets; "FREE" only for an explicitly free cart
- UPI: intentApp from get_payment_options (byte-for-byte), or generateUPIQR=true for desktop
- FREE: venueId, showId, ticketId, showTime, guestCount, latitude, and longitude echoed from create_event_cart so the server can authoritatively recreate/reprice before checkout

OUTPUTS:
- data.paasId: payment transaction ID — pass to check_payment_status
- data.orderId: echo to check_payment_status + confirm_order
- data.upiIntentUrl: UPI deeplink (handled by UI — do NOT open yourself)
- data.isQrFlow: true = QR rendered; false = the selected UPI app is opened
- data.maxTimeToPollForInMs: polling window resolved from the payment provider

For paid UPI, the payment UI handles polling + confirm automatically. Do NOT call check_payment_status in a tight loop. Free tickets return an order ID immediately; trust the returned booking status and call get_event_booking_status if it is still PROCESSING.

| Param | Type | Required | Notes |
| --- | --- | --- | --- |
| `cartKey` | `string` | yes | Cart key from create_event_cart. |
| `paymentMethod` | `"UPI" \| "FREE"` | yes | Use "UPI" when create_event_cart returns checkoutMode=UPI. Use "FREE" only when it returns checkoutMode=FREE. |
| `intentApp` | `string` | no | UPI app id from get_payment_options (e.g. "com.phonepe.app"). Echo byte-for-byte. Omit for QR flow. |
| `generateUPIQR` | `boolean` | no | true for desktop scan-QR flow. |
| `venueId` | `string` | no | Required only for FREE tickets; echo from create_event_cart. |
| `showId` | `number` | no | Required only for FREE tickets; echo from create_event_cart. |
| `ticketId` | `string` | no | Required only for FREE tickets; echo from create_event_cart. |
| `showTime` | `number` | no | Required only for FREE tickets; echo the show_time_unix used for create_event_cart. |
| `guestCount` | `number` | no | Required only for FREE tickets; echo from create_event_cart. |
| `latitude` | `number` | no | Required only for FREE tickets; echo from create_event_cart. |
| `longitude` | `number` | no | Required only for FREE tickets; echo from create_event_cart. |

### `report_error`  ·  Support · mutating

Generate an error report to share with the Swiggy MCP team. Use this when the user encounters an error and wants to report it. Returns a pre-filled mailto: link and a human-readable summary. The user can click the link to open their email client with the report ready to send. IMPORTANT: Always include toolContext with the specific identifiers from the failed tool call — e.g., orderId, restaurantId, addressId, spinId, menu_item_id, couponCode, query, cartId, slotId, paymentMethod. Include whichever IDs were part of the failed request so the team can trace the exact issue.

| Param | Type | Required | Notes |
| --- | --- | --- | --- |
| `tool` | `string` | yes | Name of the tool that errored (e.g., "checkout", "search_products", "place_food_order") |
| `domain` | `string` | no | MCP server name where the error occurred (e.g., "im", "food", "dineout"). Auto-detected if not provided. |
| `errorMessage` | `string` | yes | The error message the user saw |
| `flowDescription` | `string` | no | Brief description of what the user was doing (e.g., "searched for milk → added to cart → checkout failed") |
| `toolContext` | `object` | no | Key-value pairs of identifiers from the failed tool call. Include ALL relevant IDs such as: orderId, restaurantId, addressId, spinId, menu_item_id, couponCode, query, cartId, slotId, paymentMethod, guestCount, itemId — whichever were part of the request that failed. |
| `userNotes` | `string` | no | Any additional notes or context the user wants to share |

### `search_events`  ·  Discover · read-only

Scenes (Events & Shows): Auto-suggest search for a SPECIFIC artist name or show name. Use ONLY when the user names a specific person or exact event title (e.g. "Zakir Khan", "Anshu Mor", "Munawar Faruqui"). Returns at most 4 suggestions — this is intentional (it is an auto-suggest endpoint, NOT a full catalogue search). 

Do NOT use this for genre/category queries like "comedy shows", "music events", "open mic" — those will return only 1 result or nothing. For genre browsing: call discover_events first to get collection chip IDs, then call get_events_collection with the Comedy/Music/etc chip. 

Required: query (specific artist or show name). Optional: latitude/longitude or addressId for location context. 

If no results: inform the user and suggest calling discover_events instead. Do NOT retry the same query.

| Param | Type | Required | Notes |
| --- | --- | --- | --- |
| `query` | `string` | yes | Search keyword or event/artist name (e.g. "comedy", "Zakir Khan", "Punjabi night"). |
| `latitude` | `number` | no | User latitude for location context (optional). |
| `longitude` | `number` | no | User longitude for location context (optional). |
| `addressId` | `string` | no | Address ID from get_saved_locations. Server resolves coordinates automatically. |
